# macOS Sequoia base image (2026-10-26)

## Toolchains base

The pool's base disk is now
`/var/lib/runner-appliances/base/macos-sequoia-15.7.7-runner-toolchains-20261026.qcow2`:
the templates base of 2026-10-23 (`BASE-20261023.md`, itself the debloated
base of 2026-09-24 plus both runner templates) with
`install-runner-toolchains.sh` run as the listener account, as the pool
README has required since the pool existed. It is a standalone qcow2, no
backing file, 86.1 GiB on disk with a 256 GiB virtual size.
SHA-256: `f6e76275d0e4a558311a084ba967d6e47ac1da88e6b5fccf89fa99bd7359566e`.
The NVRAM seed is still `OVMF_VARS-sequoia-debloated-20260924.fd`, the SSH
host key is unchanged, and no listener or registration exists in the base.

## Why

The templates base of 2026-10-23 was made for the runner templates only.
The old per-instance guests had carried Rust and the Android SDK in their
own disks, so nothing in the pool base had them. Every macOS health check
after the rebuild of 2026-10-23 failed on `Verify build tools`:

```
rustc is missing from PATH
cargo is missing from PATH
adb is missing from PATH
Android SDK 35 platform/build tools are missing
```

A pool guest only has what its base carries. Each base needs the full
toolchain set before it is frozen; a template-only base is never enough.

Verified inside the maintenance guest with the health check's own tool
loop under the runner template's PATH, plus a `cargo build` of a fresh
crate. Every tool the macOS health check lists was found.

## How it was made

A maintenance guest was started from an overlay on the 2026-10-23 base
exactly as the pool starts a runner guest (the appliance image's own
start command behind `/usr/local/bin/nomercy-appliance-start`, the same
mounts, balloon and QMP socket, `-p 127.0.0.1:51999:10022`, 8 vCPU /
8 GiB), reached over SSH with the guest credential the agent holds,
`install-runner-toolchains.sh` was copied in and run as `user`, the
installer's downloads and log were removed, the guest was shut down with
`/sbin/shutdown -h now`, and the overlay was flattened with
`qemu-img convert -O qcow2` once QEMU had exited. The `.native.json`
attestation was written with the agent's own `base_identity` and checked
by instantiating `NativeProvisioner` against it before the switch.

Switching bases is all-or-nothing: both macOS runners were stopped,
retired, and created again after `appliance_pool.base_disk` in the
appliance host's `agent.json` named this file and `runner-agent` was
restarted. `Install-ApplianceHost.ps1 -PoolBaseDisk` is the setting to
pass on a reinstall.
