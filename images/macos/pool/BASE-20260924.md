# macOS Sequoia base image (2026-09-24)

## Debloated image

The reusable macOS 15.7.7 runner disk is
`/var/lib/runner-appliances/base/macos-sequoia-15.7.7-runner-debloated-20260924.qcow2`.
It is a standalone qcow2, with no backing file. Its matching UEFI variable seed
is `/var/lib/runner-appliances/base/OVMF_VARS-sequoia-debloated-20260924.fd`.
The disk is 92,430,467,072 bytes (86.1 GiB) with a 256 GiB virtual size;
SHA-256: `83d2c25a56e554376315171070edca802516e4774f1804332493e449b8c889d7`.
The 131,072-byte NVRAM seed SHA-256 is
`a25fa9e790edcc2621d0e8623b751858e7d35ca44cfc08bdc941fe898dd83644`.
The seed is copied per guest and mounted writable at
`/home/arch/OSX-KVM/OVMF_VARS-1024x768.fd`. It records disabled authenticated
root, required for the modified system snapshot. Use `NOPICKER=true` for normal
boot. The disk and seed are owned by UID/GID 1000 with mode 0600.

The active system snapshot has 62 Apple GUI app bundles removed: `Chess.app`
plus 61 bundles from `/System/Applications` and optional
`/System/Library/CoreServices/Applications`. These include Messages, Mail,
Maps, Photos, FaceTime, Freeform, TV, Music, News and App Store. The remaining
`/System/Applications` apps are System Settings, Terminal, Activity Monitor,
Screenshot, System Information, Console and Disk Utility. The Dock has no
pinned apps. Git, Python and Xcode 16.4 were checked after reboot.

The original non-purgeable Apple `com.apple.os.update-*` system snapshot remains
in the APFS volume. Both normal macOS and Recovery refused its deletion with
`-69863: Insufficient privileges`. It is not the boot snapshot, but its old app
bytes remain in the disk image for Apple's rollback mechanism. Safari also
remains in Apple's sealed OS cryptex; the writable Safari shortcut was removed.
Do not describe this image as a forensic purge of all Apple apps. The active
macOS system and Dock are debloated.

The `org.forgejo.runner` launchd job and registration are absent from this
base, so instances can register independently. The runner templates, Xcode,
Homebrew, Chrome, Firefox and Edge remain. The base was built and boot tested
on an isolated network, with no connection to the controller.

The shared production guest now uses
`/home/runner/macos_runner/data/mac_hdd_debloated.qcow2`, a writable overlay
backed by this base, and a private copy of the NVRAM seed. Its Forgejo
registration was restored only into that overlay. The original production disk
`/home/runner/macos_runner/data/mac_hdd_ng.img` and compose backup
`/home/runner/macos_runner/docker-compose.yml.before-debloat-20260924` remain
available for rollback. The runner reported successful declaration and polling
after cutover; the agent service and guest container were active.

## Earlier clean image

The macOS runner host has a private, standalone QEMU disk at
`/var/lib/runner-appliances/base/macos-sequoia-15.7.7-runner-clean-20260924.qcow2`.
It was cloned from the powered-off shared guest, prepared on an isolated Docker
network, and exported with `qemu-img convert` so it has no backing file. The
production guest was restarted before the isolated changes began.
The file is 92,432,367,616 bytes on disk (86.1 GiB), with a 256 GiB virtual
disk. SHA-256:
`2e4a2bab200fe7d3002e3bf4b50b4ceb40b6f3a7cbc2384b48d8286d8856add4`.

This is a **clean runner base, not a fully debloated macOS image**. It boots the
original Apple-signed macOS 15.7.7 system snapshot with authenticated root
enabled. The system apps under
`/System/Applications` remain. Deleting even one app and blessing a new
unsealed snapshot caused this particular QEMU guest to restart during boot;
the signed snapshot booted again. The writable `/Applications/Safari.app`
shortcut was removed, but Safari's OS cryptex remains.

The old `org.forgejo.runner` launchd job is persistently disabled, its plist
and registration directory are absent, and the old `/usr/local/forgejo-runner`
installation was removed. The installed GitHub and Forgejo runner templates
remain under `/Users/runner/templates`. Xcode 16.4, Chrome, Firefox, Edge,
Homebrew, and the command-line tools remain for jobs. Old per-user keychains,
Azure CLI state, Forgejo setup downloads, and shell history were removed from
the clone. This image is intended for the private runner host; it is a copy of
an existing installation and has not been certified for external distribution.

The standalone disk passed `qemu-img check` and booted from a new qcow2 overlay
using the wrapper's stock OpenCore and UEFI files. In that fresh instance,
macOS SSH, both runner templates, the persistent listener disable, Xcode's
developer directory, and `xcrun --find clang` were verified. The stock
OpenCore/UEFI configuration reports a custom SIP profile even though
authenticated root is enabled. The disk is owned by UID/GID 1000 with mode
0600 on the host.

The Docker-OSX wrapper image ID used for the build is
`sha256:ab06f62364694bc5c49b41ea9644d42da03f7af2b36d86acec008a725ae6e745`.
The existing recovery image is
`/var/lib/runner-appliances/bases/BaseSystem.img`.

The per-runner pool migration is separately pending. Its configuration must use
the existing guest `user` account and password file, the pinned wrapper image,
the debloated base disk and NVRAM seed paths above. `NOPICKER=true` is required
for normal startup.
